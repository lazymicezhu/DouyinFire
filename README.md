# DouyinFire

Mac 上的本地抖音续火花工具。双击应用，所有日常设置都在一个本地网页中完成。使用 Playwright 操作抖音网页元素，不使用像素坐标，不接入大模型。

**在线体验：** [打开体验站](https://plotworkers.lazymicezhu.com/)

## 打开与首次设置

1. 完成下文的本地构建后，双击 `~/Applications/DouyinFire.app`。应用会自动打开本地控制页，日常使用不需要终端。
2. 添加账号，点击 **扫码登录**，在出现的抖音窗口完成扫码或平台验证。应用会保存独立登录状态，并自动检查静默模式是否可用。
3. 填写默认消息，添加联系人并选择 **私聊** 或 **群聊**。保存后点击 **选择联系人** 或 **选择群聊**，从读取到的会话中选择目标并确认绑定，无需复制主页链接。确认显示的姓名或群名正确。每个对象可单独填写消息；留空使用默认消息。私聊也保留折叠的主页链接入口。
4. 首先对一个已绑定联系人使用 **立即执行**，在抖音中检查结果。确认无误后再开启 **每天自动执行**。
5. 如需重启电脑后继续运行，在“设置与运行详情”中点击 **开启登录后后台运行**。

默认不开启每日任务。首次登录、登录失效或遇到平台验证码时需要人工操作；正常检查、绑定和发送使用无界面的 Chromium。关闭控制页不会关闭后台，**退出后台** 会关闭每日任务和登录后恢复。

当前构建面向 Apple Silicon Mac，包含 Python、Playwright 和匹配版本的 Chromium，无需另装运行环境。使用本地签名，未进行 Apple 公证或在线发布。

## 发送与结果

- 每个账号使用独立的浏览器资料目录，并核对真实账号标识。私聊绑定稳定的抖音主页标识；群聊绑定平台会话标识，打开群后再次核对群身份，不依赖昵称或群名唯一性。
- 私聊和群聊列表只读取抖音网页当前已加载的会话。列表没有目标时，先在该账号的抖音网页中打开对应会话，再重新读取；私聊也可使用主页链接入口。读取列表和核实绑定本身不会发送消息；切换私聊／群聊类型后必须重新绑定。已有私聊绑定及发送记录会继续保留。
- GUI 手动执行和每日任务走同一条发送流程。同一账号向同一联系人在同一天已经确认发送后，再次执行会跳过。
- 只有取得可核实的消息结果才显示“已发送”。按钮点击或输入完成本身不代表发送成功。
- 发送动作可能已经发生，但没有确认结果时，记录为 **待核实** 并停止后续发送。重启或跨日也不会自动重发。
- 对待核实项，先在抖音中检查，再选择“我已核实：已发送”或“我已核实：未发送”。选择未发送只解除暂停，仍需手动执行；不会立即发送或交给定时任务重发。
- **停止任务** 会取消等待并关闭工作浏览器。已进入发送阶段的任务仍可能标记为待核实。

每日任务按设置的时区运行，默认香港时间。时间浮动值每天固定，重启不会重新抽取。电脑睡眠期间不能发送；唤醒后只在当天补执行窗口内执行一次，默认窗口为 180 分钟，不补发过去多天的任务。

抖音页面变化、登录过期或无法确认收件人时，应用会显示原因并停止相应操作，不会绕过验证码或猜测发送对象。

## 如何验证

建议按以下顺序验收，不需要终端：

1. **启动**：双击应用，应打开控制页；重复双击应复用同一个后台。
2. **静默连接**：完成登录后点击“检查连接”，应显示“连接正常”，且不弹出浏览器窗口。
3. **联系人**：选择“私聊”或“群聊”类型并保存，从对应列表中选择并核实绑定；同名对象须按列表中的身份标识区分。私聊的主页链接方式仍可使用；错误链接、当前账号本人或无法核实的对象应显示失败。群聊不能填写个人主页代替。
4. **单条发送**：仅启用一个测试联系人，设置明确的测试内容后执行。在抖音中检查内容和对象，并核对网页上的结果。
5. **防重复**：当天再次执行同一联系人，应显示跳过，抖音中不应出现第二条。修改昵称或消息后也不能绕过当天去重。
6. **停止与恢复**：任务中点击停止；若出现待核实项，先人工检查后再处理，不能直接自动重试。
7. **后台**：在设置中临时将时间浮动设为 0，设置一个稍后的执行时间，开启每日任务并保存，再开启登录后后台运行，关闭网页；到时重新打开应用检查结果。当天已发送时，预期结果是新的执行记录显示“跳过”。测试结束后可关闭每日任务。

源码自动化测试使用合成账号、模拟页面和隔离资料目录，不会向真实联系人发送消息。真实平台的投递验收仍需完成第 4 步，不能用模拟测试结果代替。

## 数据与旧版迁移

应用数据默认保存在本机：

```text
~/Library/Application Support/DouyinFire/
  config/douyinfire.yaml     配置
  data/profiles/<账号ID>/    独立浏览器登录状态
  data/tasks.sqlite3        任务状态与防重复记录
  data/runs/                每次执行记录
  logs/                     后台日志
  screenshots/              诊断目录
  backups/                  旧版迁移备份
```

首次从旧项目启动时，会备份并迁移配置和可用的浏览器资料；旧运行记录保留在原项目。原项目数据保留；迁移后默认关闭定时任务，要求重新核对账号和联系人。旧版“成功”日志没有可靠发送证据，不会当作新账本中的已确认发送记录。

不要在浏览器运行时同步、替换或复制资料目录。不要将登录状态、真实配置、聊天记录或任务数据库上传到仓库。当前数据目录位于本地 Application Support，避免 iCloud 项目同步干扰浏览器锁。

更换应用位置前，先在网页中点击“退出后台”。移动应用并从新位置重新打开后，再点击“开启登录后后台运行”，让系统使用新的应用路径。

## 开发与本地构建

以下命令仅用于开发者。日常使用直接双击应用。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pip install -r scripts/requirements-build.txt
python -m pip install pytest
python -m pytest -q
python scripts/build_macos.py --output "$HOME/Applications"
```

更新构建前先在网页中“退出后台”。构建器使用当前 Mac 对应的架构，把 Chromium 和运行环境包含在指定目录的 `DouyinFire.app` 中，并验证本地签名。构建在本机完成，不上传代码或产物。打包后的应用不依赖源码目录、构建虚拟环境或用户的浏览器缓存。

应用应直接构建到本机非同步目录。iCloud 会异步给应用包添加 FinderInfo 等属性，可能使项目 `dist` 副本的签名校验失败；因此使用上面的本机输出路径，不从 iCloud 中的应用副本启用后台服务。

源码模式可以用 `python -m douyinfire.desktop` 打开同一控制页。维护命令 `python -m douyinfire.cli doctor` 会实际启动一次空白 Chromium 检查运行环境；不访问抖音、不发送消息。

## 主要模块

| 模块 | 职责 |
| --- | --- |
| `desktop.py` / `gui.py` / `gui_html.py` | 双击启动、仅本机可访问的网页和操作接口 |
| `manager.py` | 独立工作进程、进度、取消、进程退出恢复 |
| `browser.py` | 静默浏览器、页面定位、账号/联系人/消息核验 |
| `tasks.py` / `ledger.py` | 统一执行流程、持久账本、去重与不确定结果处理 |
| `scheduler.py` / `service.py` | 时区、每日调度、macOS 登录后恢复 |
| `config.py` / `identities.py` / `runtime.py` | 原子配置保存、私聊与群聊身份、本地数据目录和迁移 |

本地控制页仅绑定 `127.0.0.1`，写操作校验来源和随机请求令牌。配置保留不相关字段，防止网页编辑覆盖其他账号。
